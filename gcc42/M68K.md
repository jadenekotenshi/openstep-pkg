# gcc42 on m68k-next-openstep4

Status: **work in progress.  The compiler proper (`cc1`) builds as a Linux cross
compiler; the assembly it produces for the samples in `m68k-asm/` is accepted by
the stock `as` on a NeXT 68k machine.  Generated code has not been run yet.**

## What is there

- Apple's tree has the `m68k-*` entries in `gcc/config.gcc` but no
  `gcc/config/m68k` directory, as with SPARC.  `gcc-m68k-config-4.2.1.tar.gz`
  holds the FSF GCC 4.2.1 `gcc/config/m68k` files, unpacked over the source
  before the patch (see `sources`).
- `gcc/config.gcc`: `m68k-next-*` uses `nextstep.h m68k/next.h`, the shared
  Mach-O/NeXT code (`nextstep.c`, `nextstep-protos.h`) and `m68k/t-next`.
- `m68k/next.h` is the m68k counterpart of `i386/next.h` and `sparc/next.h`.  It
  is based on GCC 2.95.3's `m68k/next.h`, the last FSF version that supported
  NeXT's 68k machines (NeXT support was removed after that).
- `m68k/t-next` and `m68k/ARCH_INCLUDE.h` are the SPARC ones with the architecture
  name changed: the system headers are copied from
  `/NextDeveloper/Headers/*/m68k` to `include/*/__next_m68k__`.
- `gcc/final.c`: Apple's `MAX_CODE_ALIGN` was only defined where the target has an
  instruction `length` attribute, which the 4.2.1 m68k back end does not.
- `gcc42/build`, `test` pick the target from `arch(1)` (`GCC42_ARCH` overrides).
  The target is `m68k-next-openstep4`, like the other architectures (OPENSTEP 4.2 runs on the 68k machines).

## Choices made without a machine to check them on

- **Default CPU**: 68020 instructions, bit-fields and 68881/2 floating point,
  scheduled for the 68040 (`-m68020-40`), so the same code runs on a 68030+68882
  and on a 68040.  Like GCC 2.95 did.
- **MIT assembler syntax** (the m68k default, `movel a0@+,d0`), as the stock cc does.
- The frame pointer is spelled `a6`, not `fp` (4.2's `m68k.h` prints `fp`).
- Structures are returned as GCC always did on NeXT (`PCC_STATIC_STRUCT_RETURN`
  is not defined); `STRUCTURE_SIZE_BOUNDARY` is 16; stack boundary 32 bits.
- Case vectors are pc-relative `.word` tables in the text section, the form the
  4.2.1 `m68k.md` supports.  GCC 2.95's NeXT port used absolute tables in `.const`.
- Trampolines call `__enable_execute_stack`; the instruction cache is cleared
  with `trap #2` (both from GCC 2.95's port; not verified).
- Objective-C: the sparc `STRUCT_VALUE_OFFSET` special case is not used.

## Checking the assembly

On a NeXT 68k machine, from `gcc42/m68k-asm`:

    sh check-asm.sh

assembles every sample `.s` (generated here by the cross `cc1`) with the stock `as`
and reports what it rejects.  `data.c` is also what to compare with the stock
`cc -S` output (`native-data.c` in `../sparc-asm` does this for SPARC).

## Running generated code

`check-asm.sh` only shows the stock assembler accepts the text.  In `m68k-run`,
`selftest.c` is a self-checking program (integers, long long, 68881 floating point,
varargs, structure passing and returning, switch tables, alloca, bit-fields,
printf).  `selftest-O0.s` and `selftest-O2.s` are what the cross `cc1` made of it
(`selftest.c` itself was checked with a host compiler first).  On a 68k machine:

    cd m68k-run && sh run-tests.sh

links each with the stock `cc` and runs it.  Calls to `__divdi3` and the other
libgcc routines are resolved by the stock cc's own library until libgcc is built.
